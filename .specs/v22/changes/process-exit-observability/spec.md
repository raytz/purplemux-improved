# 服务进程退出原因记录

## 用户需求与范围

用户要求补充 Purplemux 服务死亡原因记录，使端口停止监听并留下陈旧锁时，能够判断服务是正常关闭、升级切换、启动失败、收到信号还是运行中异常退出。

本需求只增加 CLI 生产服务监督器与服务进程的生命周期诊断，不改变 Electron 生命周期，不增加自动重启策略，也不改变 tmux 会话保留语义。

## 行为约定

- CLI 监督器记录子服务启动、就绪、父进程停止请求和最终退出；退出记录必须同时保留退出码与信号，不能把信号退出折算成成功退出。
- 每条记录包含时间、监督器 PID、子进程 PID、版本、运行目录、启动阶段、退出原因和已运行时长；不可用字段显式为 `null`，不猜测原因。
- 生命周期事件追加到 `~/.purplemux/logs/process-lifecycle.jsonl`；最近一次退出原子写入 `~/.purplemux/last-exit.json`，目录不存在时创建为仅当前用户可访问。
- 日志写入失败不得阻止服务启动、升级回退或退出；失败信息写入 stderr。
- 监督器必须区分父进程收到的 `SIGINT`、`SIGTERM`、`SIGHUP`、升级切换、启动超时、端口不一致、更新激活失败、spawn 错误和无预期上下文的子进程退出。
- 已就绪子进程被信号终止时，监督器以非零状态退出；正常的父进程停止和升级切换沿用现有退出或切换流程。
- 服务进程在未捕获异常成为致命异常之前输出包含 PID、异常来源、错误名称、消息和堆栈的结构化 stderr 记录，但不吞掉异常或改变 Node 默认退出行为。
- `SIGKILL`、宿主断电或监督器自身被直接杀死无法由子进程自报；子进程的 `SIGKILL` 由仍存活的监督器记录。监督器自身死亡仍依赖外部服务管理器或下一次启动时的陈旧状态判断。

## 验收标准

1. 测试覆盖正常退出、非零退出、`SIGTERM`/`SIGKILL`、父监督器停止、升级切换、启动超时及 spawn 错误，断言原因、退出码和信号不丢失。
2. 已就绪子进程收到意外信号时监督器不再以 0 退出；父监督器主动停止仍保持既有成功语义。
3. 生命周期 JSONL 可连续追加，`last-exit.json` 始终为完整 JSON；模拟磁盘写入失败时原监督流程继续。
4. 未捕获异常诊断不注册 `uncaughtException` 恢复处理器，不阻止 Node 默认终止。
5. 相关 CLI 测试、TypeScript 检查、改动文件 ESLint 和构建通过，结果记录实际命令与限制。
